# HireMind 新前端规划

## 目标与原则

新前端定位为“求职准备工作台”，把原有的简历、职位、分析、模拟面试能力收束为一个连续工作流。视觉采用参考图的深色应用外框、浅色内容工作台、圆角数据卡和克制的绿 / 橙 / 紫状态色；不复制旧版的暖色文档风。

工程使用 Vite + React 19 + TypeScript + Tailwind CSS 4，组件层采用 shadcn/ui 的可维护本地源码模式。所有页面只通过 `src/lib/api.ts` 访问 FastAPI，避免在组件里写请求细节。

## 信息架构

| 一级模块 | 用户任务 | 首屏重点 |
| --- | --- | --- |
| 总览 | 快速判断准备状态与下一步 | 匹配度、最近分析、待办面试、AI 建议 |
| 简历 | 编辑、版本管理、导入导出 | 简历列表、编辑器、实时预览 |
| 职位 | 保存与管理 JD | 职位列表、搜索、JD 详情 |
| 分析 | 运行并查看 7 节点分析 | 输入选择、实时进度、报告 |
| 模拟面试 | 开始、继续和复盘面试 | 阶段计划、对话、评分 |
| 历史 | 回看分析及面试记录 | 时间线、筛选、详情 |
| 设置 | 配置模型与本地服务 | 模型供应商、连接状态 |

## 页面与状态设计

1. `AppShell`：顶栏、主导航、当前对象上下文和响应式抽屉。
2. `Dashboard`：聚合数据，不持有业务真相；从 resume / position / analysis / interview 四个查询读取摘要。
3. 编辑类页面采用 URL 参数保存当前资源 ID，例如 `/resumes?resume=...`；筛选条件使用 URL search params，避免刷新丢失。
4. 运行中的分析以 SSE 事件更新 React Query 缓存；离开页面后可从分析 ID 恢复状态。
5. 写操作后精准失效对应资源和 dashboard 查询，不做全局刷新。

## 数据接入顺序

1. 将 `app/studio/lib/api.ts` 与类型逐步迁移为 `src/lib/api.ts` / `src/lib/types.ts`，先接健康检查、简历、职位和历史摘要。
2. 接入 Dashboard 的聚合查询与真实“当前对象”选择器。
3. 接入分析的 SSE 进度与报告页面。
4. 接入模拟面试对话与导出；最后完成设置与 Ask 助手。

## 本次实现范围

已经完成可运行的 React 工作台原型：参考图的三栏桌面布局、响应式移动导航、状态指标、分析曲线、流程卡、面试卡、AI 建议、上下文面板，以及主题切换和“新建会话”弹窗。导航会切换到对应模块的占位工作区；后续按上面的接口顺序替换为真实页面和数据。
