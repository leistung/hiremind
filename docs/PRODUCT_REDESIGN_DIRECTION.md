# HireMind · Product Redesign Direction

## 产品一句话

**HireMind 是求职者的“准备指挥台”：把素材、岗位分析、练习和行动建议集中在一个持续推进的准备计划中。**

它不是简历编辑器，也不是 AI 聊天壳；用户打开后首先应该知道：我正在准备哪个岗位、准备到哪里、现在最该做什么。

## 设计语言

参考的界面方向被保留并强化：

- 深色、微渐变的应用外壳，表达“私人工作空间”而不是普通网页。
- 浅色中央画布，承载高密度但不压迫的工作内容。
- 左侧是导航与最少的当前对象；右侧是即时上下文和系统状态。两者只在大屏展示，避免挤压主任务。
- 强橙分析卡是整个系统的“核心事件”；绿、紫、橙仅用于成功、进行、风险三种状态。
- 卡片是行动容器，每个卡片必须能去到下一步，不做纯装饰统计。

## 重新命名核心概念

| 旧称呼 | 新称呼 | 真实含义 |
| --- | --- | --- |
| 新建会话 | 新建准备 | 不制造空会话；引导用户建立简历、职位或分析 |
| 分析记录 | 准备计划 | 一个岗位的一次完整准备主线，后端仍用 `analysis_id` 持久化 |
| 历史 | 准备档案 | 回看已经完成、暂停、取消的准备计划与面试 |
| Ask 悬浮球 | 准备助手 | 只能围绕当前计划的报告、题目、答案和待办工作 |

## 第一屏应该解决的问题

1. **我现在在准备什么？** 右侧上下文显示当前简历、职位与最近计划。
2. **我现在进行到哪里？** 橙色分析卡 + 7 节点流程显示阶段。
3. **下一步应该做什么？** 待办、面试和 AI 建议卡直接给行动入口。
4. **如果我是新用户呢？** 空状态不展示假数据，显示“添加简历 → 添加职位 → 创建岗位分析”的可点击路径。

## 主路径

```text
素材库（简历、职位）
        ↓
新建准备（选择两份素材）
        ↓
岗位准备计划 / analysis_id
        ↓
分析报告 → 备考行动 → 模拟面试 → 复盘归档
```

## 实施边界

已经重建的内容是应用 Shell 和真实数据驱动的工作台。接下来不应继续添加散页，而应按以下顺序完成：

1. 为 `analysis_id` 建立 URL 路由和“准备计划”详情页。
2. 完整迁移素材库（结构化简历、头像、模板、导出与职位搜索）。
3. 把 7 节点分析、完整报告和导出放进准备计划，而不是孤立的分析表单。
4. 完整支持多阶段面试：阶段建议、笔试、逐题评价、晋级与恢复。
5. 最后接入当前计划感知的准备助手与行动待办。
