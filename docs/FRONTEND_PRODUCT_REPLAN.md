# HireMind 前端产品重构规划

## 产品定义

HireMind 应是一个以目标岗位为单位的求职准备系统，而不是“简历工具加几个独立 AI 页面”。用户在一个岗位准备计划中完成：选择简历、录入 JD、获得分析报告、处理待办、模拟面试和复盘。

简历与职位是可复用素材；分析报告和面试记录属于一次准备计划。当前后端已把 `analysis` 作为可持久化、可恢复的主线对象，故前端不应创造没有后端实体的“新建会话”。

## 现状问题

1. `新建会话` 不会创建资源，只跳至分析页，概念与行为不一致。
2. 为缩小两侧栏而移除了右侧上下文，用户切换页面后不知道当前处理哪份简历、哪个岗位或分析。
3. 默认多阶段面试包含笔试、阶段总结与推进；当前新前端仅能做逐题回答，真实流程会卡住。
4. 简历编辑器暂时缺少教育、工作、项目、技能、头像和模板功能，低于 Studio 原能力。
5. 页面状态没有 URL 化；刷新、复制链接后不能恢复资源、分析或面试。
6. 工作台只有资源数量，没有“最近计划、下一步动作、进行中状态”。

## 目标信息架构

```text
工作台（行动中心）
├── 准备计划                 ← 核心：每一项是一次 analysis 工作区
│   ├── 概览：匹配度、风险、下一步
│   ├── 分析报告：节点、场景、题库、建议
│   ├── 备考待办：将建议转成任务
│   └── 模拟面试：阶段计划、笔试、问答、复盘
├── 素材库
│   ├── 简历
│   └── 职位 JD
├── 历史
│   ├── 已完成/已取消准备计划
│   └── 已完成模拟面试
└── 设置
```

“分析”是创建准备计划的入口；创建成功后应自动进入 `/plans/:analysisId`，而不是留在一张表单页。

## 布局规则

- 左侧主导航固定 **176px**，只放核心模块。
- 中间为主工作区，最大宽度约 **1120px**。
- 右侧为仅桌面端显示的上下文栏，宽 **280px**；在准备计划/面试中显示当前简历、职位、分析状态与下一步，在素材编辑页隐藏。
- 顶栏按钮为“开始准备”，打开明确的三项分流：完善简历、添加职位、开始岗位分析。

## 关键用户流

### 首次使用

开始准备 → 导入/创建简历 → 添加职位 JD → 确认输入 → 创建分析 → SSE 进度 → 自动进入准备计划概览。

若缺少简历或职位，按钮要说明缺口并跳转对应页面，不进入空白分析页。

### 已有素材

开始准备 → 选择简历和职位 → 可填写计划名 → 创建分析。计划名默认“公司 · 职位 · 日期”，并保存到 analysis metadata。

### 备考与面试

分析完成 → 生成且可编辑面试阶段方案 → 确认启动 → 支持笔试批量提交、逐题回答、阶段总结、下一阶段、最终报告和中断恢复。

## 后端建议

第一阶段可复用现有接口。第二阶段增加聚合读取端点：

`GET /api/plans/{analysis_id}/workspace`

它返回分析摘要、关联简历/职位摘要、最近面试状态、未完成建议与下一步动作。先从现有 `AnalysisStore` metadata 聚合，无需立刻新增数据表。

## 实施顺序

1. 基础：React Router、URL 参数、查询缓存、加载/错误/空态，恢复右侧上下文栏。
2. 素材库：完整迁移 Studio 的结构化简历编辑、头像、模板、导出及职位搜索。
3. 准备计划：分析创建向导、SSE 恢复、7 节点和完整报告/导出。
4. 面试：阶段推荐/编辑、笔试、逐题、晋级、报告、恢复。
5. 行动中心与 Ask：最近状态、备考待办、上下文感知助手；通过全流程验收后移除 Studio。

验收标准：刷新后能恢复状态；每个 CTA 实际调用 API 或清晰告知不可用；任何一条首次使用路径都能完整走到分析报告。
